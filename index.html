Abstract

We present CineNeural, an explainable movie recommendation system built on a Decision Network — a probabilistic graphical model that combines a Bayesian Network (for uncertainty reasoning over user and item features) with a Utility Function and a Decision Node (applying the Maximum Expected Utility principle to select recommendations). Trained and evaluated on the MovieLens 100K dataset, our system achieves Precision@10 = 0.312, NDCG@10 = 0.387, AUC-ROC = 0.724, and catalogue Coverage = 0.641, while providing per-recommendation causal explanations — a capability absent in all collaborative filtering and matrix factorisation baselines tested.

1. Introduction

Recommendation systems are central infrastructure in modern digital platforms — Netflix, Amazon, and Spotify all rely on them at massive scale. The dominant approaches (collaborative filtering, matrix factorisation, deep learning) achieve impressive accuracy but are fundamentally opaque: they cannot explain why a recommendation was made, making them unsuitable in regulated domains (finance, healthcare) and eroding user trust.

Decision Networks (also called Influence Diagrams) extend Bayesian Networks with decision and utility nodes, providing a principled probabilistic framework for decision-making under uncertainty. In this project, we apply a Decision Network to movie recommendation: the network models the conditional probability that a user will like a movie given observable features, computes the Expected Utility of recommending it, and applies the Maximum Expected Utility (MEU) criterion to rank candidates.

2. Theoretical Background

2.1 Bayesian Networks

A Bayesian Network is a Directed Acyclic Graph (DAG) G = (V, E) where each node Vi represents a random variable and each edge encodes a conditional dependence. The joint distribution factorises as:

P(X1, …, Xn) = ∏i P(Xi | Pa(Xi))

where Pa(Xi) is the set of parents of Xi in the DAG. Inference is performed using Variable Elimination, computing the posterior P(query | evidence) by marginalising over hidden variables.

2.2 Decision Networks (Influence Diagrams)

A Decision Network extends a Bayesian Network with two additional node types:

  • Utility Node: A deterministic function U(parent states) mapping outcomes to numerical utility values.
  • Decision Node: A node whose value is chosen by the agent (recommend or skip) to maximise expected utility.

The optimal decision under uncertainty follows the Maximum Expected Utility (MEU) principle:

d* = argmaxd ∈ D EU(d | e) = argmaxd Σo P(o | e, d) · U(o, d)

2.3 Conditional Probability Table Estimation

We estimate CPTs using Bayesian estimation with a BDeu prior (equivalent sample size = 5), which: (i) prevents zero-frequency problems for unseen combinations; (ii) encodes a weak uniform prior over states. This is equivalent to adding a pseudo-count to every cell in the frequency table.

3. Methodology

3.1 Dataset

MovieLens 100K contains 100,000 ratings (1–5) from 943 users on 1,682 movies, collected between September 1997 and April 1998. We apply a temporal train/test split: for each user, the most recent 20% of their ratings are held out as the test set. This mimics real deployment conditions better than random splits, which leak future information into the training set.

3.2 Feature Engineering

The following discretised features are used as Bayesian Network nodes:

  • user_activity: rating count → {low, medium, high} (tertile bins)
  • user_rating_bucket: mean rating → {harsh, neutral, generous} (fixed thresholds 2.5, 3.5)
  • item_popularity: rating count → {niche, moderate, popular} (tertile bins)
  • item_quality: mean rating → {low, medium, high} (same thresholds)
  • item_genre: primary genre tag from u.item metadata

3.3 Utility Function

We define a simple asymmetric utility function: U(rating_positive=1) = +1.0, U(rating_positive=0) = −0.5. The asymmetry encodes that a bad recommendation has moderate negative cost (user frustration), while a good recommendation has high positive value. The threshold θ = 0.3 was chosen to balance precision vs. recall on a held-out validation set.

5. Discussion

The Decision Network achieves competitive performance vs. user-based collaborative filtering while being ~10% behind SVD on ranking metrics. However, SVD provides zero explainability and cannot handle cold-start users. The Decision Network handles cold-start naturally: given only demographic features, the network marginalises over unknown preferences to compute a still-meaningful posterior.

Coverage advantage: The Decision Network recommends 64.1% of the catalogue vs. 49.7% for SVD. This is significant — SVD overconcentrates on items with many ratings (popularity bias), while the Decision Network's genre-conditioned structure encourages diversity.

Limitations: Discretising continuous features (ratings, counts) loses granularity. The network assumes conditional independence given parents — a strong assumption. Future work could use Conditional Gaussian BNs for mixed data or learned structure via score-based methods (e.g., BIC/AIC).

6. Conclusion

We demonstrated that a Decision Network is a viable and uniquely explainable approach to movie recommendation. While it does not surpass SVD in raw accuracy, it provides causal reasoning, cold-start capability, and catalogue diversity — properties essential in production systems where user trust and diversity matter. The MEU decision framework cleanly separates the uncertainty model (Bayesian Network) from the value model (Utility Function), making it easy to adapt the system to different business objectives by simply changing the utility values.
